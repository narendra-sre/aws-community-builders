# Article 05 — IAM Policy Security Review Workflow

**From Wildcards to Least Privilege: Building a No-Infrastructure AWS IAM Policy Security Review Workflow**

This project demonstrates a small, explainable review workflow for IAM identity policies. It compares an intentionally over-permissive example with a scoped S3 example using:

1. A local Python JSON policy checker that detects selected patterns only; it is not a full IAM parser.
2. AWS IAM Access Analyzer `ValidatePolicy`.
3. AWS IAM Policy Simulator `SimulateCustomPolicy`.

The workflow is review-only. It does **not** create IAM users, roles, managed policies, S3 buckets, analyzers, EC2 instances, or other AWS resources. It does not attach either sample policy to an identity and does not perform S3 data-plane operations.

> **Cost note:** No AWS infrastructure is provisioned by this project. This is not a guarantee that all activity in an AWS account is free. Check current AWS pricing and your account billing information independently.

## Prerequisites

- Ubuntu 24.04 / WSL2 or another Linux shell.
- Python 3.10 or later.
- AWS CLI v2.
- AWS credentials configured locally for an identity permitted to call `access-analyzer:ValidatePolicy` and `iam:SimulateCustomPolicy`.
- Network access to the AWS APIs for the two AWS-based stages.

No AWS access key or secret should be placed in this project. Do not paste credentials or full credential/config files into chat or commit them to Git.

## Run from the project root

```bash
# Make the shell scripts executable
chmod +x scripts/*.sh

# 1. Offline check; does not contact AWS
./scripts/audit-policies.sh

# 2. Validate both policies using Access Analyzer
./scripts/validate-policies.sh

# 3. Simulate an allowed, explicit-deny, and implicit-deny case
./scripts/simulate-policies.sh

# 4. Capture fresh outputs from your own execution
./scripts/capture-evidence.sh
```

The local checker intentionally reports findings for the deliberately insecure sample. Those findings are expected demonstration output, not a failed project run. Malformed JSON or unreadable files should cause a non-zero exit.

The capture script runs the local checker, validates both policies, and records the selected simulator results. Run it after making any policy or script changes so the evidence corresponds to the current files.

## Expected simulator cases

| Action | Resource | Expected decision from the supplied policy |
|---|---|---|
| `s3:PutObject` | `arn:aws:s3:::article05-demo-bucket/telemetry/sample.json` | `allowed` |
| `s3:DeleteBucket` | `arn:aws:s3:::article05-demo-bucket` | `explicitDeny` |
| `s3:DeleteObject` | `arn:aws:s3:::article05-demo-bucket/telemetry/sample.json` | `implicitDeny` |

These are expected outcomes for the supplied identity policy and simulation inputs. Verify the actual output from your run. They are not proof that a real request would succeed in an AWS account; real authorization can also depend on identity, resource, permissions-boundary, session, Organizations policies, and request context.

## Cost and resource boundary

The workflow does not provision AWS infrastructure or perform S3 data-plane operations. The AWS-based stages call policy-validation and policy-simulation APIs. Check current AWS pricing and your account billing information; this repository cannot guarantee that unrelated activity in your AWS account will incur no charges.

## Cleanup

No AWS resources are created by these steps, so no AWS teardown is required. The cleanup script is for local evidence only. To remove generated result files manually:

```bash
rm -f evidence/results/*
```

This removes the contents of `evidence/results/`; it does not remove screenshots or policy files.

## Limitations

- The Python checker detects only a deliberately small set of risky patterns. It is not a complete IAM policy parser, policy evaluator, or security scanner.
- A clean local check or an empty Access Analyzer findings list does not prove a policy is safe for every workload.
- The Policy Simulator evaluates the supplied policy and simulation context; it does not recreate every control in a real request path or perform an actual S3 operation.
- The bucket name and ARNs are illustrative. No bucket is created or contacted.
- Expected simulator decisions should be checked against the actual output generated from the current policy documents.

## Safety reminder

Never attach `policies/overprivileged-policy.json` to a real IAM user, group, or role. Keep credentials, tokens, private keys, and AWS configuration files outside this repository.
